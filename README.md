# 每日热量计算器 · 云端版

一个单文件的中式饮食热量计算器：内置 460+ 条中式食物库（14 个分类），支持在线查询包装食品、
拍照识别营养成分表，自动计算 BMR / TDEE / BMI 与每日目标热量。

数据保存在云端账号下，换设备登录同一邮箱即可继续。

## 功能

- **今日饮食**：关键词/条码搜索食物，自动汇总热量与三大营养素，对照目标给出建议
  - **日期选择器**：可回看过去任意一天的记录并直接编辑 / 删除；新增记录写入当前查看的日期
    - 未来日期不可选；「回到今天」一键切回；标题、汇总、营养素进度随日期联动
    - 「常吃」快捷标签按全量频次统计，切换日期时不会漂移
  - 常用食物快捷标签：按分类一键筛选（14 类），「常吃」按历史频次一键加入
  - 饮食记录可编辑（份量与营养数值）与删除，汇总实时重算
  - 三大营养素目标完成度：按推荐供能比（蛋白 30% / 碳水 45% / 脂肪 25%）折算克数目标
- **我的数据**：性别 / 年龄 / 身高 / 体重 / 活动水平 → BMR、TDEE、BMI、目标摄入
  - BMI / BMR / TDEE / 目标热量四张说明卡片，点标题展开释义（每张独立展开，互不影响）
  - 每日身体数据快照入库，生成体重变化与热量摄入 vs 目标的长期趋势图
- **营养成分表**（原「拍照录入库」）：拍照识别营养成分表（调用云服务内置视觉大模型，无需自建后端、无需任何 API Key），
  校对后存入自建食物库，支持照片留存
  - 视觉模型下拉：自动列出该应用可用的、支持图片输入的模型，选择后记忆在本地
- **菜品识别**（独立页）：识别菜名、目测每种食材克数，按内置食物库每 100g 数据换算热量
  - 有自己的上传入口（拍照 / 相册 / 文件）与裁剪框，与营养成分表页互不影响
  - 食材自动匹配内置库与「我的食物库」（含 60+ 条常见叫法归一，如「鸡肉丁」→「鸡胸肉（生）」）
  - 匹配不到的食材可「AI 查热量」补一个每 100g 估值，能计入本次估算，也能一键存入自己的食物库
  - 一键把这盘菜加入今日记录；克数与热量均标注为粗略估算
  - **自建食物库自动同步**：切到本页、窗口重新获得焦点、每 60 秒自动与云端同步，顶部显示同步状态与增量
  - **识别前可裁剪**：拖动选框框住要识别的区域，裁剪后只识别这一块
    - 区域大小可自选：直接填「宽度 px × 高度 px + 左上角 X/Y」，或用快捷选区（整张 / 居中 70% / 上半 / 下半 / 左半 / 右半 / 标签位）
    - 可锁定宽高比，拖角时两侧同步变化
  - **移动端上传来源分开**：
    - 「拍照」直接调用相机（`capture=environment`）
    - 「从相册 / 文件选」不设 capture，手机弹出系统选择器，可选图库里的图或任意文件
    - 桌面端两者都退化为普通文件选择框
  - **触摸拖动裁剪框**：手指拖动与四角缩放均可用，把手触摸热区放大到 30px 以上
  - **识别前可裁剪**：拖动选框框住要识别的区域，一次裁剪对营养表识别与菜品识别同时生效
    - 区域大小可自选：直接填「宽度 px × 高度 px + 左上角 X/Y」，或用快捷选区（整张 / 居中 70% / 上半 / 下半 / 左半 / 右半 / 标签位）
    - 可锁定宽高比，拖角时两侧同步变化
- **自建食物库**：跨设备同步，支持导出 JSON / CSV
- **体验**：首次使用三步引导、逐字段范围校验、深浅色主题、移动端适配

## 技术实现

- **单文件应用**：整个应用就是一个 `index.html`，无构建步骤，双击即可运行
- **后端**：WorkBuddy 云服务（认证 + 数据库 + 对象存储）
- **SDK 内联**：云服务 SDK 直接内联进 HTML，不走 CDN
  （部分浏览器的跟踪防护会拦截第三方 CDN 脚本访问 storage，导致登录静默失败）
- **数据隔离**：所有表均以 `owner_id` 归属用户，行级安全策略确保用户只能读写自己的数据

### 数据库表

| 表 | 用途 |
|---|---|
| `profiles` | 身体数据、目标、BMR / TDEE 计算结果 |
| `food_logs` | 每日饮食记录（日期、克重、热量、三大营养素） |
| `custom_foods` | 自建食物库（含营养成分表照片的对象存储路径） |
| `body_metrics` | 历史身体数据快照（每日体重、身高、BMR、TDEE、目标热量） |

四张表均为 `owner_id TEXT DEFAULT auth.uid()` + RLS 行级安全，
客户端不发送 `owner_id`，由数据库填充并强制校验。
